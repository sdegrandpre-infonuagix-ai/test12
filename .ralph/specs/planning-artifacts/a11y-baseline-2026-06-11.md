# Accessibility Baseline Audit — test12 (Story 0.10 / UX-DR17)

**Date:** 2026-06-11
**Story:** Epic 0, Story 0.10 — *Verify existing UI accessibility baseline*
**Standard:** WCAG 2.1 Level AA
**Status:** ✅ Zero serious/critical violations across all three audited views.

---

## 1. Why this story exists

UX-DR17 requires the *existing* UI (header chrome + core flows) to meet WCAG
2.1 AA **before** the upcoming Voice-Mode Switcher (Epics 1+) commits to AA,
so the switcher does not inherit unfixable accessibility debt from its
surrounding context. This is a baseline gate, run after the Tailwind
migration (Stories 0.1–0.9) was complete.

## 2. Tooling & method

| Item | Choice |
|------|--------|
| Engine | **axe-core 4.x** via **`@axe-core/playwright`** |
| Browser | Real headless **Chromium** (Playwright) |
| Harness | [`tests/a11y-audit.test.js`](../../../tests/a11y-audit.test.js) (+ [`tests/support/static-server.js`](../../../tests/support/static-server.js)) |
| Run | `npm run test:a11y` (exit non-zero on any serious/critical WCAG A/AA violation) |
| Rules | tags `wcag2a, wcag2aa, wcag21a, wcag21aa` |

**How the views are reached.** `public/index.html` is a single-page app where
the public feed, private-channel sections, and auth modal all coexist in one
DOM, gated by auth state. The harness serves `public/` over loopback HTTP,
stubs `/api/**` at the network layer (so the SPA boots and renders *real*
component markup with no live backend/DB), and aborts external origins (Google
Fonts, Google/Apple sign-in SDKs) for deterministic, offline-safe runs. CSS
transitions/animations are frozen before each scan so axe never samples a
mid-fade composited colour.

**Views audited (per AC):**
1. **Unauthenticated landing** — login modal auto-open.
2. **Authenticated public-feed** — `onLoggedIn()` + sample posts rendered.
3. **Private-channel view** — a private channel active with messages loaded.

## 4. Findings fixed in this story

The only serious violations found were **colour-contrast** (WCAG 1.4.3, AA).
All were dim greys used as *text* on the near-black surface (`#050810`) or, in
the auth modal, a too-light grey on white. The brand tokens themselves
(`text-text-muted = #64748b`, `brand-teal = #1595b2`) were **left unchanged**
(they remain valid for borders/accents and are guarded by
`tests/tailwind-smoke.test.js`); only the failing *text* usages were bumped to
the palette's existing accessible secondary-text grey `#94a3b8`.

| Element | Before | After | Contrast before → after |
|---------|--------|-------|--------------------------|
| `.btn-primary` (Connect) | white on `#1595b2` | white on `#0e7490` | 3.51 → ≈5.4:1 |
| `.channels-section h2` (section headings) | `#64748b` | `#94a3b8` | 4.2 → ≈7.4:1 |
| `.logs-header h3` (Agent Log) | `#64748b` | `#94a3b8` | 3.99 → ≈6.8:1 |
| `.channel-panel .ch-meta` | `#64748b` | `#94a3b8` | 3.95 → ≈6.5:1 |
| `.ch-empty` (empty states) | `#475569` | `#94a3b8` | 2.64 → ≈7.4:1 |
| `.powered-footer` | `#475569` | `#94a3b8` | 2.64 → ≈7.4:1 |
| `.profile-badge` | `#64748b` | `#94a3b8` | 4.2 → ≈7.4:1 |
| `#aliases-section > p` | `#64748b` | `#94a3b8` | 4.2 → ≈7.4:1 |
| `.aub-label` (usage bars) | `#64748b` | `#94a3b8` | (small text) → ≈7.4:1 |
| `.login-divider` ("or") | `#9ca3af` on white | `#6b7280` on white | 2.53 → ≈4.8:1 |

Files touched: [`src/styles/tailwind.css`](../../../src/styles/tailwind.css),
[`public/index.html`](../../../public/index.html) (inline `<style>` + two inline
attributes). `public/dist/tailwind.css` rebuilt via `npm run build:css`.
Existing regression checks (`tailwind-smoke`, `class-coverage`) still green.

## 5. Filed follow-ups (out of scope for Story 0.10)

These are **not** WCAG A/AA serious/critical (so they do not block the
baseline) but should be addressed. The switcher work (Epic 1) must not
reproduce them.

| # | Finding | axe rule / source | Severity | Recommendation |
|---|---------|-------------------|----------|----------------|
| A11Y-1 | Heading order skips `<h1>` → `<h3>` (Agent Log before the `<h2>` section headings) | `heading-order` (best-practice) | moderate | Demote "Agent Log" `<h3>`→`<h2>` or restructure so levels only increase by one. |
| A11Y-2 | 3 content blocks sit outside a landmark (`#addon-usage-bars`, `#pwa-banner`, `#login-overlay` are siblings of `<main>`) | `region` (best-practice) | moderate | Wrap/relocate under appropriate landmarks or add `role`s; add a skip-to-content link. |
| A11Y-3 | Icon-only buttons rely on bare emoji as their accessible name (`✕` close, `+`/`✓` alias, `✕` PWA dismiss) | manual | minor/moderate | Add explicit `aria-label`s (e.g. "Close", "Add alias", "Dismiss"). Some already have `title`; prefer `aria-label`. |
| A11Y-4 | `.btn-danger` (Disconnect) white-on-red contrast not evaluated (button is `disabled` on load → axe skips it) | not evaluated | unknown | Verify white on `#dc2626`/`#ef4444` gradient ≥4.5:1 in the enabled/active state. |
| A11Y-5 | No automated coverage of the Profile & Plans modal or phone/OTP login steps (not opened in the 3 audited states) | coverage gap | — | Extend the harness to open `#profile-modal` and the OTP step, or audit manually. |
